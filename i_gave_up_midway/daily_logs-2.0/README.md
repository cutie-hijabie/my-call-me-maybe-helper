# Daily Logs — Restarted Workflow

These are my Call Me Maybe daily logs from the point where I changed the way I work on the project.

The day numbering continues from my original daily logs. I am **not** starting again from Day 1 because this is still the same project and the work I did before this still matters.

The difference is the workflow.

Earlier in the project, I often worked forward until I found a problem, went backwards to fix it, and then continued. That taught me a lot, but eventually it became frustrating because I did not always have a clear boundary between:

- something I had already built
- something that was broken
- something that was simply not implemented yet
- something that belonged much later in the project

From Day 12 onward, I am working in clearer stages based on actual program capabilities.

Each log will focus on what I was trying to make work that day, what existing code I reused, what I changed, what I observed when I ran it, what went wrong, what I learned from the failure, and what is still intentionally unfinished.

These logs are **not tutorials** and they are not meant to show a perfect solution.

They are my actual learning record.

Sometimes the output will be wrong. Sometimes I will discover that an earlier assumption was wrong. Sometimes I will stop and reorganize the work again.

I want to keep those parts because they are part of understanding the project.
